## 0. 왜 재구성하나 (한 문단)

기능과 정책은 대부분 정해졌습니다. 그런데 그 결정이 **문서 5종·화면 ID 15계열·제안서 3건**에 흩어져 있고, 낡은 본문이 "충돌하면 PLAN을 따른다"는 머리말 한 줄로만 무효화돼 있습니다. 그 결과 **SCREEN_SPEC(핵심 8화면)이 10-29 이후의 결정(14일 만료·동시 3통·교류 종료·잠시 쉬기·완료 화면·다음에 물어보기)을 거의 반영하지 못한 상태**입니다. 시각 콘셉트가 정해지면 바로 정식 화면 제작으로 넘어가야 하는데, 지금 기준으로는 화면마다 문서 3~4개를 겹쳐 읽어야 합니다. 이 제안서는 새 기능을 추가하지 않고, 이미 정한 것을 **하나의 뼈대**로 다시 묶습니다.

### 1.2 구조 문제 (어긋남의 원인)

1. **관계 상태가 정의된 곳이 없다.** ‘첫 편지 보냄·받음·교류 중·보관·종료·차단·만료·쉬는 중’이 문서 곳곳의 문장으로만 존재해서, 새 정책이 추가될 때마다 영향받는 화면을 사람이 기억해서 찾아야 합니다. G1·G4가 이렇게 빠졌습니다.
2. **화면 목록이 3곳에 나뉘어 있다.** M=SCREEN_SPEC, A·D·P·S=PRODUCT_PLAN, C=COMPANION, 나머지=PLAN §6. 한 화면의 진입·나가기가 다른 문서의 화면과 이어지는지 확인할 곳이 없습니다.
3. **공통 상태가 화면마다 반복된다.** 로딩·오프라인·실패·글자 200% 등이 화면별 문장, PROPOSAL_STATE_SCREENS, DESIGN_BRIEF 품질 기준에 각각 적혀 있습니다.

## 2. 재구성 원칙 [추천]

1. **기준 문서는 셋.** 왜·무엇(PLAN) / 어떻게 보이고 움직이나(SPEC) / 공통 규칙(STATES). 나머지는 기록 보관.
2. **관계 상태 표가 화면보다 먼저.** 모든 버튼 판단은 상태 표를 가리키고, 화면 문서는 "이 상태에서 무엇을 보이는지"만 적는다.
3. **화면 ID는 바꾸지 않는다.** Figma 프레임 이름과 제안서들이 기존 ID를 쓰고 있어 번호를 새로 매기면 비용이 큽니다. 대신 **탭별 한 목록**으로 모읍니다.
4. **새 기능 추가 없음.** 이 제안서의 모든 항목은 기존 결정의 재배치이거나, 결정이 빠진 곳을 [미정]으로 드러내는 것입니다.

## 4. 관계 상태 — 모든 화면의 뼈대 [추천]

### 4.1 상대 한 사람과의 관계 상태

| 상태 | 들어오는 조건 | 나가는 조건 | 내가 할 수 있는 것 |
|---|---|---|---|
| **없음** | 기본 | 첫 편지 보냄 / 받음 | 소개 보기, 첫 편지 쓰기(대기 자리 있을 때) |
| **첫 편지 보냄** | 첫 편지 전송 성공 | 상대 답장 → 교류 중 / 14일 → 만료 / 내가 정리 | 보낸 편지 읽기. 추가 발송 불가 |
| **첫 편지 받음** | 상대의 첫 편지 도착 | 내가 답장 → 교류 중 / 14일 → 만료 / 내가 정리 | 읽기, 답장 쓰기, 정리, 신고, 차단 |
| **만료** | 14일 동안 답장 없음 | (되살아나지 않음) | 읽기 전용(받은 쪽은 ‘지난 요청’). 같은 사람에게 첫 편지 다시 보내기 불가 |
| **교류 중** | 첫 편지에 대한 실제 답장 전송 성공 | 종료 / 차단 | 편지 쓰기(연속 허용), 수첩, 보관, 종료, 신고, 차단 |
| **종료** | 어느 한쪽이 교류 종료 | (되살아나지 않음) [미정: 다시 시작 허용 여부] | 기록 읽기 전용(R03). 양쪽 모두 새 편지 불가 |
| **차단** | 어느 한쪽이 차단 | 내가 해제(상대도 차단 중이면 유지) | 기록 읽기, 초안 복사·삭제. 상대에게는 ‘지금 이 사용자에게 편지를 보낼 수 없어요’ |

**관계 상태와 따로 움직이는 표시(겹칠 수 있음):** 보관함에 있음 · 새 편지 있음 · 초안 있음 · 전송 중/결과 불명 · 상대가 쉬는 중 · 상대 계정 이용 불가.
→ 이렇게 나누면 "보관했는데 새 편지가 오면?"(보관 해제, 관계는 그대로), "쉬는 사람에게 편지를?"(교류 중이면 가능, 첫 편지는 불가) 같은 질문이 표 한 번으로 답해집니다.

### 4.2 나 자신의 상태 (계정 단위)

| 상태 | 효과 |
|---|---|
| 새 친구 받기 끔 | 새 첫 편지를 받지 않음. 추천에서 제외 |
| 잠시 쉬기 | 위와 같음 + 기존 친구에게 ‘편지 교류를 쉬고 있어요’. 끄면 이전 ‘새 친구 받기’ 값으로 복귀 |
| 대기 자리 0/3 ~ 3/3 | 3/3이면 새 첫 편지 쓰기 불가 [미정: 쓰기는 허용하고 보내기만 막을지] |
| 영어 도움 남은 횟수 | 0이면 도움만 불가, 편지는 계속 |

### 4.3 버튼 판단 순서 (PRODUCT_PLAN §9를 위 상태에 맞게 다시 씀)

계정 사용 가능 → 차단·상대 이용 가능 → **종료·만료** → 전송 중/결과 불명 → 기존 초안 → 관계 상태 → **대기 자리** → 보고 있는 편지
(굵은 글씨가 10-29 이후 결정으로 새로 끼워야 하는 단계입니다.)

## 7. 결정이 필요한 것 (이 제안서가 정하지 않은 것)

1. **G7 일상 소개 vs 오늘의 한 장면**: (가) 둘 다 둔다 — 한 장면은 짧은 대표 문장, 소개는 긴 글 (나) 한 장면이 소개를 대신한다. 추천은 (가)지만 가입 단계가 하나 늘어납니다.
2. **대기 자리 3/3일 때**: 첫 편지 쓰기 버튼을 막을지, 쓰기·초안 저장은 허용하고 보내기만 막을지.
3. **종료된 교류를 다시 시작할 수 있는지**: PLAN §4.4는 "양쪽 모두 새 편지를 보낼 수 없다"까지만 정함.
4. **M02 행에 남은 기간을 보일지**: "14일 남음" 같은 표시는 카운트다운처럼 느껴질 수 있음(PLAN §4.1 ‘카운트다운 금지’와 같은 결).
5. **배지 숫자 하나의 뜻(G9)**: 추천은 "숫자는 항상 새 편지 수, 전체 개수는 숫자 없이".
6. **영어 도움 이름(G6)**: 추천은 메뉴 이름을 ‘함께 답장 생각하기 / 문장 다듬기 / 뜻 확인’으로, ‘표현 찾기’는 버리기.
7. **문서 재구성을 실제로 할지**: 승인하면 순서는 STATES.md 작성 → SCREEN_SPEC v2(이번 표의 ‘할 일’ 반영) → PRODUCT_PLAN 이전·보관 → PLAN §6을 링크로 교체 → 부록 A #56 추가.
