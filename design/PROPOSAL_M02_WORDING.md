## 2. 결정이 필요한 것
- **탭 숫자의 뜻**: 우편함 칩의 "첫 편지 1"은 새 편지 수, "보관 2"는 전체 수입니다. M02 탭의 "받은 편지 1"도 새 편지 수라서 같은 모양의 숫자가 앱 안에서 두 가지 뜻을 씁니다. 하나로 통일할지, 지금처럼 두고 소리 이름만 구분할지 정해야 합니다.
- **‘정리한 요청’이라는 말**: 숨긴 요청이라는 뜻이 처음 보는 사람에게는 잘 안 읽힙니다. 다만 SCREEN_SPEC의 용어(‘요청 정리’)이고 거절 통지를 하지 않는 부드러운 어감일 수 있어 바꾸지 않았습니다. 바꾼다면 ‘숨긴 요청’이 후보입니다.
- **빈 상태와 실패 문구**: 화면용 임시안입니다. 특히 5번의 "친구 찾기" 단일 행동이 맞는지 확인이 필요합니다.
- **받은 요청 없음이 실제로 나오는 조건**: 처음 쓰는 사용자에게만 나오는지, 요청을 모두 정리한 뒤에도 나오는지(그때는 ‘정리한 요청’ 진입이 필요할 수 있음) 정해져 있지 않습니다.

## 3. 바꾸지 않는 곳
- 우편함(M01) 줄의 도시 표시: 현재 화면에서 숨겨져 있고, 이번 제안과 무관합니다.
- MINGPAL_PLAN.md는 M02의 상세 문구를 다루지 않아 수정 대상이 아닙니다(검색해 확인하지는 않았습니다).
- 신고·차단·요청 정리의 상세는 M04(더보기) 쪽이라 이 제안에 넣지 않았습니다.

## 4. 확인하지 못한 것
- SCREEN_SPEC.md 전체를 다시 읽지 않고, 위 줄 번호는 이번 세션에서 읽은 22~55행과 검색 결과 기준입니다.
- 위 문구는 화면에서 눈으로만 점검했고 사용자 반응으로 검증되지 않았습니다.
- 오프라인, 눌렀을 때의 모양, 요청이 많을 때(긴 목록·긴 이름)는 화면을 만들지 않았습니다.
